# fable5.2demo — three sentences, three games and a film

Three browser-playable 3D games plus a 10-second rendered short, all from **three sentences of requirements** ("我想做一款水下探索游戏，而且要尽可能惊艳" → [Tidebell](https://github.com/hahaliu1029/fable5.2demo); "把仙侠游戏也打磨一遍" → 青云宗·御剑采灵; "把赛博朋克做成驾驶游戏" → MOTHLIGHT), with a fourth game (MISREMEMBER) added later under different rules. No downloaded images, textures, models, fonts, music or video; no image/video/audio generation models; runtime dependency is three.js r170 only; each game packs into one offline `index.html` you double-click.

## What it is

- **Tidebell** — submarine exploration: 48 models generated by Python scripts in Blender (fish, anglerfish, whales, manta rays, shipwreck…), a hand-written underwater light model where red disappears with depth unless you turn the lamp on, ~18,000 instanced plants and rocks, fish/jellyfish animation entirely in vertex shaders.
- **青云宗** — third-person sword-flight xianxia game: volumetric cloud sea, real planar water reflection, autopilot script that can complete the game and record a replay, reproducibly.
- **MOTHLIGHT** — rainy cyberpunk street racing: seed-generated 9×9-block city, 694 buildings drawn in one instanced pass, parallax-window interiors, arcade drift physics.
- **MISREMEMBER** — first-person memory-house horror (rooms rebuilt behind your back); one shared `data/house.json` drives both the Blender modelling and the game, per-room coordinate systems stitched door-to-door with stencil masking.
- The short film is a pure function of time at every frame — fully reproducible renders.

## How it was built

Beyond the games themselves, the repo's documentary discipline stands out: **every project ships a report (README.md / REPORT.md) covering how it was implemented, how it was verified, and "做了假的地方" — where corners were cut or things faked** — plus the model's own assessment of its weaknesses. The MISREMEMBER section openly labels its Codex-generated textures as the exception to the no-generated-assets rule. Autopilot/replay scripts double as playable acceptance tests.

## What it cost

Not published. Films and `.blend` files live in Releases (too big for the repo).

## How to reproduce

Open each game's `index.html` in desktop Chrome; or `npm install && npm run build && npm test` per project; `npm run assets` regenerates models via Blender 5.2 scripts.

## What to take from it

1. **Report format: implementation, verification, and an explicit "what we faked" section.** That third heading is the trust multiplier — copy it into every agent-built project (see the [verification-first playbook](../playbooks/verification-first-content.md)).
2. **One data file shared between DCC and engine** (`house.json` → Blender models + game logic) keeps two renderings of one world from drifting apart.
3. **Autopilot scripts are acceptance tests you can watch** — "completes the game and records a replay, reproducibly" is a stronger claim than any unit test.
4. **Seed everything.** Seed-generated city + deterministic film frames make outputs checkable across runs.
